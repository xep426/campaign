Kein Bild des Widgets, sondern sein Regelwerk. Die Karte unten rechnet mit demselben Code wie WidgetMetrics.forSlot() — dieselben Faktoren, dieselben Klammern, dieselben drei Schwellen. Zieh sie an der Ecke größer und die Gestaltung ändert sich so, wie sie es auf dem Homescreen tut.

Woher die Zahlen kommen

429,7 × 233,1 dp ist gemessen, nicht geschätzt: die Voreinstellung ist der Slot, den One UI dem platzierten Widget auf dem Galaxy S23 tatsächlich gibt (appWidgetSizes aus dumpsys appwidget).

Das deklarierte Minimum 250 × 110 dp ist die Rechnung 70·n − 30 aus campaign_widget_info.xml — was Geräte unter API 31 nehmen, wo targetCell* ignoriert wird. Die Karte muss auch dort noch stimmen. Die übrigen Größen sind aus dem gemessenen Raster hochgerechnet.

Was hier stimmt

Farben, Radien, Faktoren, Klammern und Schwellen sind aus dem Quelltext übernommen. Die drei Zeilen teilen sich die Resthöhe über flex:1, genau wie defaultWeight(). Die Schrift der Karte ist bewusst eine System-Sans: Glance setzt keine fontFamily, das Widget bekommt also Roboto bzw. One UI Sans — nicht die Fraunces der App.

Was hier nicht stimmt

Zeilenhöhen sind CSS, nicht RemoteViews; die Zeilenhöhe in dp kann um ein bis zwei dp abweichen. sp wird als dp gezeichnet, also ohne die Schriftskalierung des Systems — wer sie hochstellt, bekommt auf dem Gerät größere Schrift bei gleicher Karte. Und das Abschneiden langer Titel ist die CSS-Näherung von maxLines.
